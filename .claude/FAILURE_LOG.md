Claude が外したことを 1 件ずつ残す。直近 8 件はセッション開始時にフックが読み込ませる。追記だけする。
書式: `## F-番号 日付 — ひとこと` ／ 起きたこと ／ 原因 ／ 再発防止（どのファイル・どの検査に入れたか）。
起きていないことを書かない。分からない点は「不明」と書く。

## F-03 2026-11-10 — 直す箇所の取りこぼしと、頼まれていない箇所の破壊（鍵山の報告）
- 起きたこと: 鍵山の報告。「直しているところと直していないところがある」「ここを直してと言うと平気で他を壊す」「やるなと言ったことをやる」「以前の指示を覚えていない」。個別の発生箇所はこの台帳に未記録（不明）。次に起きたら箇所つきで 1 件ずつ足す。

- 再発防止: 台帳 O-01〜O-05。`tools/claude_guard.py`（開始時の読み込み、毎回の型、終了前の自己監査）、`tools/check_invariants.py`（回帰検査）、`critical-reviewer`（他者レビュー）。

## F-04 2026-11-17 — X のポストを「読めない」と報告した（読める方法があった）
- 起きたこと: 鍵山が渡した X のポスト（x.com/xpurojekuto/status/2120798665514315923）を、x.com と中継サイトが届かないことを理由に「読めない」と 2 回報告した。鍵山「他の X も読んでるから、それと同じような方法で読んで」。web-fetch エージェントで `https://cdn.syndication.twimg.com/tweet-result?id=<ポストID>&token=a&lang=ja` を開いたら読めた。
- 原因: 環境の許可リストに cdn.syndication.twimg.com が入っていることは get_environment で見ていたのに、Bash の curl が止められた時点で手を止め、同じ URL を web-fetch エージェント（組み込みのエージェント種別。中で WebFetch の道具を使う）で開く手を試さなかった。基盤スキルの「x.com は届かない」を、X は全部読めないと広く読んだ。
- 再発防止: X のポストは、まず web-fetch エージェントで上の埋め込み用 URL を開く（本文・作者・日時・リンク・記事のプレビューが取れる）。X の記事（x.com/i/article/…）の本文はこの URL では取れないので、プレビューまでしか読めていないと明記する。置き場: いまはこの台帳だけ。基盤スキル 68 行（「x.com は届かない。URL は鍵山に聞く」）は未修正で、直すかどうかは鍵山の判断待ち。
