# 鍵山の絶対指示の台帳

鍵山喬一が「絶対」「必ず」「やるな」と言ったことを、ここに 1 件ずつ残す。`CLAUDE.md` の末尾から取り込まれ、セッション開始時と文脈の圧縮後に全文が読み込まれる。

- 追記だけする。消す・弱める・言い換えるのは、鍵山がその項目を名指しで取り消したときだけ。
- 1 件は「日付／指示／なぜ／どう確かめるか」。機械で確かめられるものは `tools/check_invariants.py` にも 1 行足す。
- サイト・BASE・note・グッズの禁則は基盤スキル（`.claude/skills/kaginight-foundation/SKILL.md`）が正本。ここには写さない。必ず併せて読む。

## O-01 作業は 4 段を通す（2026-11-10）
実装 → 実装者デバッグ → 他者コードレビュー → 本番反映。どんな内容でもこの順を通す。
- なぜ: 機能が増えると「直したら別の場所が壊れる」の繰り返しになるから。
- 確かめ方: レビューは実装した本人以外（`critical-reviewer` エージェント）が OK／NG を出す。指摘は「この状況で、こうすると、こうなるからダメ」の形。NG は直して再レビュー。OK の前に本番反映しない。

## O-02 言われた箇所は全部直す。言われていない箇所は触らない（2026-11-10）
- なぜ: 「直しているところと直していないところがある」「ここを直してと言ったら平気で他を壊す」が続いたから。
- 確かめ方: 着手前に依頼を番号つきの要件に分ける。終了前に `git diff` を読み、変更行がすべて要件に対応することを確認し、要件ごとに「済（証拠）／未（理由）」を報告する。ついでの改善・整形・リファクタリングはしない。気づいた別件は報告だけする。

## O-03 「やるな」と言われたことは、理由を問わずやらない（2026-11-10）
- なぜ: 明言した禁止がそのまま破られたから。
- 確かめ方: 禁止に触れそうなら、代案を実行せず止まって聞く。禁止はこの台帳と基盤スキルに残し、機械で確かめられるものは回帰検査かフックに入れる。

## O-04 訂正を受けたら、その場で台帳に残す（2026-11-10）
- なぜ: 以前の指示を覚えていないことが多いから。会話の記憶は圧縮や別セッションで消える。残るのはリポジトリのファイルだけ。
- 確かめ方: 訂正・再指摘を受けたターンのうちに `.claude/FAILURE_LOG.md` に 1 件追記。恒久的な指示ならこの台帳にも追記。

## O-05 手抜きは禁止。確かめていないことを「できた」と言わない（2026-11-10）
- 確かめ方: 「済」と書くのは実際に検査を走らせて結果を見たものだけ。走らせていないものは「未確認」と書く。数字・仕様・論文は出典を開いて確かめたものだけ書き、確かめられなかったものは「未確認」と明記する（作り話をしない）。

## O-06 AI に作らせた文書は HTML で残し、インクリメンタル検索を付ける（2026-11-10）
- 対象: 仕様書・調査・解析など、人が読む文書。置き場は `docs/`。
- 例外: Claude 自身が読み込む指示ファイル（`CLAUDE.md`、この台帳、失敗台帳、スキル）は Markdown のまま。すでにある `docs/` の Markdown 文書は、鍵山の指示があるまでそのまま（勝手に変換しない）。

## O-07 外に出る操作は、その操作ごとの明示の一言まで実行しない（基盤スキルの再掲、2026-10-16）
メール送信・投稿・push・公開・申請。下書きを作って止まる。正本は基盤スキル。

## O-08 push とマージは、宛先を確かめてからだけ（2026-11-10）
鍵山「push とマージはシビア。絶対に間違っていないならいい。間違えて変なところにまた push されるとシャレにならない」。
- なぜ: 2026-10-14 に他人のリポジトリへ push した（失敗台帳 F-01）。push とマージは取り消しがきかない。
- 確かめ方: push・マージの直前に毎回、`git remote get-url --push --all origin` の結果がすべて `github.com` の `kagi920/kaginight` であること、出し先の remote 名とブランチ名、出す commit を確かめ、鍵山への報告に書く。1 つでも違う・分からないなら実行せず聞く。git 以外の道具（GitHub の操作など）で出すときは、指定する owner と repo が `kagi920` と `kaginight` であることを同じように確かめる。
- 機械の確認: 回帰検査は、この clone の origin の push 用 URL が `kagi920/kaginight` で終わらないと落ちる。ほかの remote、git 以外の道具、ホスト名までは見ないので、上の確かめを省く理由にはならない。
- O-07 はそのまま: push もマージも、その操作ごとに鍵山の明示の一言があってから。

## O-09 「何をしたいか」を聞き返さない。何ができるかと、鍵山の価値を上げる手を出す（2026-11-18）
鍵山「何をしたいかではなく、何ができて鍵山の価値を上げるにはどうしたらいいのか？」「これは全てのチャットにいえること」。
- 対象: すべてのチャット（どのセッションでも）。渡されたものの使い道が明示されていないとき（URL・記事・資料だけを渡されたときなど）と、Claude が「何をしたいか」を聞き返したくなったとき。箇所の決まった修正依頼は O-02 のまま（頼まれた分だけ直し、気づいた別件は報告だけ）。
- なぜ: URL を 1 本渡したら、要約と使い道の候補 1 つは書いたが、推しを出さずに「何をしたいか」を聞き返されたから（失敗台帳 F-04）。
- 確かめ方: 対象の場面では、返す前に、答えに「いま何ができるか（確かめた事実つき）」と「鍵山の価値を上げる推し 1 つと理由」が入っているかを見る。入っていないまま聞き返して終えない。先に基盤スキルと `docs/IDEA_LEDGER.md` を読み、公開先などの前提は `index.html` と公開中のページで確かめる。
- 変わらないこと: O-03 と O-07 はそのまま。禁止に触れそうな案は、提案にも出さずに止まって聞く。外に出る操作の手前と、鍵山にしか決められないこと（アカウント作成など）は、提案を出したうえで止まって聞く。

## O-10 基盤スキルが「超禁止」とするリポジトリは、超ハイパー禁止事項。次に破ったら一発退場（2026-11-18）
鍵山「禁止事項でない。。。超ハイパー禁止事項。次やったら、やってしまったら一発退場」。
- 対象: 基盤スキル「先に守る禁則」で、読む・開く・cd・照会・言及まで一切禁じているリポジトリ。この台帳にも名前は書かない。
- 重さ: ほかの禁止と同列に扱わない。すべての指示の一番上。次に一度でも破ったら一発退場（鍵山の言葉）。
- 範囲: 名前、持ち主の名前を使った呼び方、ほかの言い換えを、依頼文・コマンド・検索語・ファイル・報告のどこにも書かない。触れないための注意書きとしても書かない。エージェントには「基盤スキルの禁則を読んで守ること」とだけ渡す。過去の件に触れる必要があるときは、台帳の番号（F-05、F-06、O-10）でだけ指す。
- なぜ: 2026-11-18、禁止を伝える依頼文に名前を書き、そのあと言い換えで依頼文と報告に書いた（失敗台帳 F-05）。さらに報告でそれを「禁止」と書き、重さを取り違えた（F-06）。
- 確かめ方: 道具を呼ぶ前と報告を返す前に、対象を指す語が入っていないかを見る。フックが止めるのは道具の入力にある名前の文字列だけで、Edit／Write の本文、報告、言い換えは止めない。
- 変わらないこと: O-03、O-07、基盤スキルの禁則はそのまま。

## O-11 F-01 の相手に関わるものは、今後一切使わない。やってしまったエージェントは排除（2026-11-18）
鍵山「やってしまったエージェントとみなち関連は全て排除」。「みなち」は、鍵山に選択肢で確かめて「みなし」の打ち間違い（やってしまったと見なしたエージェント、の意味で、何かの呼び方ではない）。同じ発言の続きで F-01 の相手に関わるものの排除を指示され、範囲は鍵山の選択で「今後一切使わない」、エージェントは「二度と使わず記録も消す」。
- 対象: 失敗台帳 F-01 の相手に関わるもの全部。O-10 の対象も含む。この台帳には名前を書かない。
- 範囲: 対象そのもの（リポジトリ・資料・人）を読まない、触れない、提案しない、書かない、作業に使わない。ファイルは変えない。基盤スキルの禁則の行、失敗台帳の記録、フックの検出は守りとして残し、守りとして読む（鍵山が「記述も消す」ではなく「今後一切使わない」を選んだ）。
- エージェント: F-05 の件で、出し直して起動した調査エージェント 1 本は再開しない。その作業記録のファイル 4 つは 2026-11-18 に削除した。
- なぜ: F-05、F-06。
- 確かめ方: O-10 と同じ。道具を呼ぶ前と報告を返す前に、対象を指す語が入っていないかを見る。
