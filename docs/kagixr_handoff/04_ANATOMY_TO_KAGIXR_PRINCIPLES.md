# AnatomyからKAGI XR A/Bへ移す設計原則（鍵山からの受領メモ、2026-10-14）

受領：Claude Code セッション session_01KR78PAyW1VQXjcvX2CesXF、2026-10-14。原文は鍵山がチャットに貼った全文。要点のみ転記し、原文の区分（公式で確認した仕組み／KAGI向け設計提案／未実施テスト計画／未確認事項）を保つ。

## 結論
- 学ぶ中心は画風ではなく「入力・動作・見える結果の因果関係を、同じ状態モデルと検証で守る」こと。KAGIでは「実打が、正しい楽器・手・スティック・軌跡へ一貫して伝わる」に置き換える。
- A案：V8の2D原画を保持し、打点に結び付いた3D軌跡と制限された空間カメラで奥行き。B案：Charakuru由来の骨付きアバターを既存Aerodrums MIDI系へ接続。
- 共通の保護条件：V8の構図、顔、スティックを握る手、フルキット。色や光沢だけの反復は進歩と数えない。
- 直近対象はMac演奏者画面とiPhoneブラウザ参加。ヘッドセット／左右眼は今回の必須要件に含めない。
- 提出条件：人物・フルキット・背景・カメラ・UIを含む10秒の全体演奏動画を同じ入力で比較できること。単打の確認は内部診断。

## 公式資料で確認した構造（Anatomy）
- 共有モデルから静的形状・動く部分・表示値を生成。SVG基本、必要な効果だけWebGL、任意の3Dモードはbeta。
- WebGL効果は背面SVG・canvas・前面SVGの間に入り、形状と同じ投影・世界座標を使う。発生と消失を連続させる。
- 検証は画面サイズ別撮影、拡大、低速連続フレーム、WebGLなし、動きを減らす設定を含む。静止画だけで判定しない。

## KAGIに適用しない項目
等角投影への統一、参照から新物体を発明する方針、部品数を品質の代用にすること、全域同一シェーディング、自動ツアーの無条件導入、SVG監査をXR全体の合格証明にすること。

## A/B共有の実装契約（提案）
- 演奏イベントを一つの基準に正規化（イベントID、時刻、楽器、強さ。左右手は存在する場合のみ）。MIDIの打撃イベントと測定姿勢を混同しない。Aerodromsが実際に出す項目はログで確認してから設計確定。
- 各ドラム／シンバルにローカル打点・打面方向・接触範囲。スティック先端・握り位置・手首は別の基準点。
- 効果は打点や先端に接続。世界に残る部分と手に追随する部分を分ける。

## A案への適用（提案）
V8を固定基準画に／立体化対象を軌跡・打撃位置・奥行きに限定／遮蔽の理由（マスク・簡易深度）／カメラ可動域を仕様化／XRなら左右眼も別判定。

## B案への適用（提案）
アセット制作と演奏制御を分離／握りを最初に成立／一打を完成させてから全キット／顔の合格を独立に置く／衝突する要件を隠さない。

## 未実施のテスト計画
同じV8基準・同じ短いイベント録音・同じカメラ経路・同じ端末でA/B比較。単打、左右交互、同時打ち、連打、キット全体移動、無入力復帰。合格項目：基準画の保全、入力一致、一打の因果、握り、前後関係、カメラとXR、時間と性能、停止・復帰。一回の変更で「症状→原因仮説→変更箇所→同一条件の前後比較→残る問題」を残す。

## 未確認
V8実データと描画コード、Aerodrums接続のイベント形式、Charakuruアセットの品質、対象端末の実測値・WebXR実装。
