## 1. 鍵山の価値（ポジショニング）

**一文**: 「実際に叩くドラマーが、その実打をそのまま信号にして、現地の人も配信の人も"叩く側"に引き込む夜をつくっている。日本でこれを続けている演奏家は他にいない。」

根拠（公開事実のみ）
- cocobat、アーバンギャルドの元ドラマー（Wikipedia）。サポートドラマーとして現場経験が長い。
- KAGI NIGHT を 2022（渋谷 B.Y.G ＋ Beat Wave の立体配信）、2026（六本木 unravel tokyo）と自主開催。
- Aerodrums／Vision Pro／OSC／TouchDesigner の自作パイプラインを GitHub で公開（kagi920）。
- 論文調査（docs/RESEARCH_SPEC.md）で、人間の XR ドラマーがライブでリアルタイム映像と AI を駆動した査読論文は見つからなかった。つまり「前例の無さ」自体が価値になる。

価値の三層（読者が払う理由）
| 層 | 読者が得るもの | 書くもの |
|---|---|---|
| 体験 | 叩く側になれる夜 | 現場の記録、参加の手順、次回の案内 |
| 制作 | 自作パイプラインの中身と失敗 | 制作ログ、設計の判断、数字（実測のみ） |
| 考え | 「身体と計算機」をどう見ているか | 短い思索、他ジャンルへの接続 |

## 2. 読者の三段階と、お金の階段

研究が示す構造（出典は docs/research_notes/creator_economy_discovery.md）
- どのプラットフォームでも収入は上位 1〜3% に集中する（Patreon 上位 1% が月 2,500 ドル以上、Regner 2021）。「フォロワー数 × 平均」で収入を見積もらない。
- 無料読者から有料に転換するのは実務者の推定で 1〜5%。有料 50 人には、関心のある読者がおよそ 1,000〜5,000 人必要。
- note は公開記事の 24.8% が有料（2024 年 11 月末、note IR）。有料記事はこの場では普通で、抵抗が小さい。
- note のメンバーシップ売上は前年比 +81.3%（2025 年 11 月、note IR）。月額の部屋は、単発の有料記事より場の勢いに合う。
- 推し活の月額支出は 7 割が 1 万円未満（afb 2025、n=500）。ファンクラブの年会費の相場は 5,000〜9,000 円。
- スーパーファンの支出は配信ではなくライブ物販と現物に集中する（Luminate、MIDiA）。

よって階段はこう組む（価格は案。決めるのは鍵山）
| 段 | 商品 | 価格の目安 | 役割 |
|---|---|---|---|
| 0 | 無料記事・X 投稿 | 0 | 知ってもらう。全記事の前半は無料 |
| 1 | 有料記事（制作ログ・現場の裏） | 300〜800 円 | 「払う人」を最初に作る |
| 2 | KAGI ROOM（note メンバーシップ） | 500〜1,000 円/月 | 配信の先行案内、制作の途中、部屋の人だけの夜 |
| 3 | ライブ・配信チケット、グッズ（受注生産） | 既存価格のみ | 一番お金が動く場所。部屋の人へ先に売る |
| 4 | 仕事の依頼（出演・制作・共同研究） | 都度 | note は「研究と実績の証拠」として働く |

重要: 配信の支払い意思は「ファンかどうか」で決まり、価格では決まらない（Onderdijk 2021 ほか）。配信もグッズも、冷たい流入にではなく部屋の人に先に売る。

## 3. note の作法（プラットフォーム側の標準）

- プロフィール: 1 行目に「XR Drummer。実打を信号にして、空間と人を動かす。KAGI NIGHT 主催。」次に実績 3 つ、最後にホームページ URL。ヘッダーはクラゲ（HP と統一）。
- 固定記事: 「鍵山喬一は何をしているか」（入口記事、無料）を常にトップに固定。
- マガジン: 「KAGI NIGHT 制作ログ」「叩く夜の記録」「考えていること」の 3 本。有料記事が 5 本たまったら有料マガジンに束ねる（note 公式の案内どおり）。
- 有料ライン: 記事の前半 6〜7 割で「何をしたか」と結論まで出す。有料部分には「数字・手順・失敗・次に試すこと」を置く。前半だけ読んでも損がない構造にする。
- 見出し画像: 現場写真か制作画面。文字入り画像は使わない（クラゲのトーンと統一）。
- 投稿の型: 冒頭 3 行で「いつ・どこで・何をした」。本文は現場の場面 → 判断 → 結果 → 次。末尾に HP と次回の案内。
- 頻度: 週 1 本。長さは 1,500〜2,500 字。短くても出す。
- X（@KAGI920）: 公開直後に 1 投稿、翌日に引用 1 投稿。記事の一文をそのまま使う。
- 計測: note のダッシュボードで「ビュー・スキ・フォロー・購入」を週 1 で記録。4 週で傾向を見る。

## 4. 書き直しの編集方針（既存記事に適用）

軸: 「技術の解説」ではなく「鍵山が何をしているか」。技術は、やっていることを説明するために出す。

| 検査 | 合格の条件 |
|---|---|
| 冒頭 | 3 行以内に、鍵山が実際にやった行為が出てくる |
| 主語 | 「私は〜した」が各節に 1 回以上。「〜という技術がある」で始めない |
| 場面 | 現場・練習・制作の具体的な場面が 1 つ以上 |
| 数字 | 実測した数字だけ。推定は「だいたい」 |
| 禁則 | 他メンバーの名前・顔、私的情報、visualgate の成果の自分事化、価格の創作、機種限定の言い方 |
| 導線 | 末尾に HP（https://kagi920.github.io/kaginight/）と、次回か KEY の案内 |
| 有料ライン | 前半だけで結論が分かる。後半に手順と失敗 |

## 6. 編集の手順（毎回）

1. ブリーフ: 読者（鍵山を知らない人か、来た人か）、目的（知る・買う・依頼）、導線を 1 行ずつ。
2. 取材: 鍵山の音声入力 5〜10 分。書き起こしのままでよい。
3. 構成: 冒頭 3 行、場面、判断、結果、次、導線。
4. 執筆: 鍵山の言葉を残す。説明語は削る。
5. 推敲: 第 4 章の検査表で全項目を確認。
6. 公開: 鍵山が note に貼る。価格と有料ラインは鍵山が最終決定。
7. 計測: 翌週、数字を記録。
