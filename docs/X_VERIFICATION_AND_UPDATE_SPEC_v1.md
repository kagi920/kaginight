## 0. 禁則（検証する GPT・代行者が守ること）

1. **投稿しない。プロフィールを変えない。フォロー・フォロー解除・ブロック・削除をしない。** 検証は「読む・数える・書き写す・スクショ」だけ。更新は鍵山が自分で貼る（§6）。
2. **お金が動く操作をしない**（X Premium の加入・解約、広告、チップ、サブスクの設定）。画面まで案内してよいが確定ボタンは押さない。
3. **サードパーティのフォロワー解析ツールにログインさせない**（X のアカウント連携を許可しない）。X 自身の画面と X Analytics だけを使う。
4. **ログイン情報・認証コードを文章に書かない。**
5. **書いてはいけないこと**（更新資料にも適用）: 他の出演者・メンバーの名前や顔、鍵山の職・収入・健康などの私的情報、visualgate-livesystem の成果（XR_DRUM、GHOST RACK、Scratch Box）を鍵山の制作物として書くこと、存在しない価格、機種限定の言い方（「iPhone で」「Safari で」）、「計算機」という語、技術・研究の説明。
6. 報告は「見たもの／数えたもの／できなかったこと」を分ける。画面で確認した事実だけを「確認」と書く。

## 2. 作業 B: 解析の枠組み（制作担当が export を受けて行う。GPT が先に埋めてもよい）

### B-1 どの層に届いているか
§A-5 の a〜g の比率で判断する。
- a（ドラマー）＋ e（業界）が多い → 仕事（サポート出演・制作）は来やすいが、ONLINE の客は少ない。客向けの投稿を増やす。
- b（客）が多い → ONLINE への導線を太くするだけでよい。
- c・d（XR・配信文化）が多い → HP の ONLINE を「参加できる配信」として見せる投稿が刺さる。
- f（海外）が一定数 → 投稿に英語を 1 行添える価値がある。
- g が多い → フォロワー減は掃除で説明できる。

### B-2 どの投稿が効くか
§A-3 の種別①〜⑥ごとに、インプレッションの中央値、エンゲージメント率（エンゲージメント÷インプレッション）、返信数の中央値を出す。
判定: 返信とプロフィールクリックが多い種別を「主力」、インプレッションだけ多い種別を「入口」、どちらも低い種別を「減らす」。
**本文に URL がある投稿と無い投稿で、インプレッションの中央値を比べる**（§3 の根拠が自分のアカウントでも成り立つか確認）。

### B-3 フォロワー減の原因の切り分け
| 観察 | 解釈 | 対応 |
|---|---|---|
| 減少日に投稿なし、g が多い | 掃除 | 気にしない。認証済みフォロワー数を基準にする |
| 減少が告知の連投（②）の直後 | 告知過多 | 告知は 1 回＋固定投稿、残りは①③④ |
| 減少が⑤（共演者告知）の後 | 他バンドの客が離れた | ⑤は引用でなく自分の演奏動画に添える |
| 投稿が長期間ゼロ | 休眠 | 週 1 の型（§5）で再開 |
| 反応はあるのに減る | 内容が層とずれている | §B-1 の層に合わせる |

### B-4 HP への流れ
- 現在 HP に訪問者計測は無い（docs/SOCIAL_LINK_SPEC_v1.md §5）。X の「リンククリック」数だけが X→HP の数字になる。
- 固定投稿のリンククリック数／固定投稿のインプレッション を「X→HP 率」とし、4 週ごとに比べる。目標値は置かない（根拠が無い）。変化の向きで判断する。

## 3. X のランキング信号（根拠。更新案はここから導く）

出典: X が 2023 年 3 月に公開した推薦システムのコード（github.com/twitter/the-algorithm）の説明と、その解説記事。以下の重みは公開時点のもので、X はその後も変更を続けている。**数値は方向の目安であり、現在の値ではない。**[公開コード 2023 ／ 現在の重みは未確認]

| 信号 | 公開時の重み（目安） | 運用への翻訳 |
|---|---|---|
| 返信に投稿者（鍵山）が返す | 最も強い正（約 75） | 来た返信には必ず 24 時間以内に返す |
| 返信される | 強い正（約 13.5） | 問いかけ・答えやすい一文で終える |
| プロフィールをクリックしてさらに反応 | 正（約 12） | プロフィール文と固定投稿を「次に押せる」形に |
| リポスト | 正（約 1） | — |
| いいね | 弱い正（約 0.5） | いいね狙いの投稿は効率が悪い |
| 動画を半分以上見る | 正（小） | 10〜30 秒の動画。冒頭 1 秒で叩く |
| 「興味なし」「ミュート」「ブロック」 | 強い負（約 −74） | 連投・同文の繰り返しを避ける |
| 通報 | 最も強い負（約 −369） | — |

他に公開コードから分かること:
- 認証（Premium）アカウントの投稿はランキングで優遇される（公開時の係数: フォロワーには ×4、非フォロワーには ×2）。[公開コード 2023 ／ 現在は未確認]。加入するかは鍵山の判断（費用が発生する）。
- 候補の約半分はフォロー外から来る（Out-of-Network）。フォロワー数より「誰が反応するか」が効く。
- 外部リンクの扱いは一次資料で確定できない（経営者の発言はあるが公式文書が無い）。**本文に URL を入れず、返信欄か固定投稿に置く**運用にする（§B-2 で自分のデータでも確かめる）。
- 2025 年以降、X は推薦を自社 AI（Grok）ベースへ移すと発表している。[報道 ／ 仕様は未公開]。方向として「投稿の内容そのものが読まれる」ので、本文に「ドラム」「リズム」「グルーヴ」「XR」「KAGI NIGHT」の語を自然に入れる。

## 5. HP との連結（X と HP が一緒に上がる仕組み）

### 5-1 すでに HP にあるもの（v21）
- X へのリンクに `rel="me"`、構造化データの `sameAs` に X の URL（同一人物の認識）
- ONLINE シートの「開催の知らせは X で届く（@KAGI920 をフォロー）」
- LIVE シートの「X で友だちに知らせる」（文面・URL・ハッシュタグ入り）
- X に URL を貼ったときのカード（クラゲの画像＋一文、twitter:creator）

### 5-2 流れ（循環）
```
X の投稿（動画・一文）
  → 返信欄 or 固定投稿の URL → HP（クラゲ）
  → ONLINE シート（参加 URL・日時）→ 配信に来る
  → LIVE シートの「X で友だちに知らせる」→ X へ戻る（新しい人が見る）
  → PROFILE シート → note（読む人）／ KEY（部屋に入る人）
```
X は「見つかる場所」、HP は「来る場所」。両方に同じ語（XR ドラマー、KAGI NIGHT、ドラム・リズム・グルーヴ）を置くことで、検索と推薦の両方で同じ人物として積み上がる。

### 5-3 検証結果を受けて HP に入れる更新（制作担当が行う）
- §A-3 の上位投稿のうち演奏動画があれば、その投稿 URL を PROFILE シートの「X（@KAGI920）」バーの直下に「叩いている動画を見る」として置く（埋め込みはしない。軽さを保つ）。
- §B-1 で c・d（XR・配信文化）が多ければ、ONLINE シートの一文を「参加できる配信」が前に来る順に調整する。
- `?from=x` の受け口は今は不要。計測を入れる判断（Cloudflare か GoatCounter）が出たら対応する。
