## 2. ホームページ側で実装したこと（v18）
- 本人確認リンク: note・X・Instagram・GitHub へのリンクに `rel="me"` を付与。構造化データの `sameAs` と合わせ、検索エンジンと各サービスが「同一人物」と認識できる形。
- 共有ボタン: LIVE シートに「X で友だちに知らせる」（文面と URL とハッシュタグ #KAGINIGHT #XRドラマー を自動で入れる）。
- フォロー導線: ONLINE シートに「開催の知らせは X で届く（@KAGI920 をフォロー）」。
- カード: X に URL を貼るとクラゲの画像と一文が出る（og:image、twitter:creator）。

## 3. プラットフォームの公式説明から導く運用（出典つき）
- Instagram は単一のアルゴリズムではなく、フィード・リール・ストーリー・発見で別々に順位付けする（Mosseri 2023 年 5 月 31 日、about.instagram.com）。2025 年の説明では、投稿はまず小さな初期視聴者に出し、視聴時間・保存・共有の反応が良ければ広げる。フォロワー数だけでは決まらない。
- X の公開コードでは、返信とそれへの投稿者の反応が最も強い正の信号、通報やブロックが最も強い負の信号。外部リンクの扱いは一次資料で確定できないため、本文には書かず返信欄か固定投稿に置く運用にする。

## 5. 計測（決めること）
GitHub Pages には訪問者数の記録が無い。X や Instagram からどれだけ来たかを知るには、無料の計測を 1 つ入れる必要がある。候補は Cloudflare Web Analytics（無料、Cookie なし）か GoatCounter（無料、Cookie なし）。どちらも鍵山のアカウント作成が要る。入れない場合は、X と Instagram の「リンクのタップ数」だけで見る。

## 6. 鍵山が用意するもの
1. X と Instagram の現在のプロフィール画面のスクショ（文面・リンク・フォロワー数）。
2. 直近の投稿で反応が良かったもの 3 つ（URL）。何が効いたかを型に反映する。
3. 10〜30 秒の縦動画の素材（叩いている手元か全身）。無ければ撮る予定日。
4. 計測を入れるか（Cloudflare か GoatCounter か、入れない）。
